# Windows TURN relay preparation

Refs #6561. Activation is held until the VPS IP cutover is verified. No public listener, firewall, service, routing, DNS or Main change is made by preparation.

Use the official coturn native x64 artifact pinned in `records/turn/coturn-windows.json`. The tag source and successful MSVC push run are recorded, along with both archive hashes and every selected runtime file. The upstream tag is unsigned and no artifact attestation was supplied; trust is the official repository/run provenance plus the GitHub artifact digest. Its executable reports 4.19.0 because that exact source retains the same fallback build version. Do not substitute binaries based on the display version.

The native package includes its dependency DLLs and runs without a runtime/SDK installation. It is a foreground console program, with no Windows Service Control Manager implementation in the pinned source. The deployment plan uses the existing Thornswood task-SID owner launcher, LOCAL SERVICE with only SeChangeNotifyPrivilege, and no SYSTEM fallback. Protected code/config are read-only to the task SID; only its log/state directory is writable.

The controlled task must run from its protected config directory and use a relative config basename: upstream `find_config_file` recognizes only slash/tilde absolute paths, so Windows drive-letter paths silently fall back to defaults. The process arguments also carry the nonsecret exact bind, UDP-only and auth-required constraints. Missing/wrong config, hash drift or unexpected listeners are refusals, not fallback modes. Coturn 4.19 DTLS and CLI are opt-in; obsolete no-dtls/no-cli options are not used.

Existing Oracle allocation/bandwidth limits are preserved. Dev uses UDP listener3478 and media42000–42031 on Windows, user-quota8, total-quota32, max-bps65536 and bps-capacity2097152. Each relay receives a separate secret, with the old Oracle credential configuration retained for rollback. A username is currently the issuer’s numeric expiry, so user-quota limits a credential bucket; it must not be described as a unique identity or IP quota. Existing HMAC-SHA1/expiry issuer behavior stays unchanged.

Before activation, finish security/dependency review and record the isolated acceptance. After cutover, prove the new address/reply source, exact allowed UDP ingress/range, secret ACLs and controlled task identity. Then swap only the Dev issuer, run public two-host actual relay media, and let the reviewed normal Dev release proceed. Main is staged separately on listener3479 and media42032–42063, with its own key/task/realm and acceptance; it receives no Dev credentials by copying. Both ranges are below the measured Windows IPv4/IPv6 UDP dynamic start49152, with zero existing bindings observed during read-only preflight.

Retain the verified upstream archive in the protected deployment tool store and the installed versioned package/manifest for durable rollback. Future installs must use that pinned retained archive or a newly reviewed pin: an expiring upstream CI artifact alone is not a durable installer source.

## Reviewed package and host sequence

`New-CoturnPackage.ps1 -Archive <retained-official-archive> -OutputDirectory <new-staging-child>` checks both nested archives and every selected byte before writing a new staging child. It never runs the vendor installer. Runtime files and the coturn licence are copied; the installer retains the upstream archive in the protected operations store. This is an operator-only server dependency, never a game/client payload.

`Install-CoturnRelay.ps1 -Step Stage -Role dev -RelayIPv4 <verified-new-address> -Archive <retained-official-archive> -SourceCommit <reviewed-operations-source>` is run on the VPS only after the actual preferred source address is verified. It creates a disabled task and a fresh separate key. `-Step Activate` is Dev-only; it opens only the exact program/address/listener/media ingress in the canonical Group Policy store, verifies actual firewall scope and PID endpoints, and starts no issuer. Failure disables the task and removes only its named ingress rule. `-Step Stop` is the reverse for that owned task/rule; protected files remain for inspection. Main activation is refused by the script.

`Switch-DevTurnRelay.ps1 -Step Inspect -RelayIPv4 <verified-new-address> -ExpectedDevCommit <actual-dev-source>` reads only counts and identity. `-Step Switch` requires zero peers and zero in-world profiles, preserves the existing task-SID owner action, stores the original action/key in an admin/SYSTEM-only transaction receipt, and atomically changes the protected Dev key and the single relay URL binding. It verifies the served short-lived HMAC credential and unchanged Main identity. A failure after stopping restores the old protected key/action. `-Step Rollback -ReceiptDirectory <exact-receipt>` is the controlled later Oracle rollback; the Windows relay is stopped separately only after the issuer is verified back. No old key is deleted or printed, and no uncertain chat is replayed.

Before each activation, verify scoped port use and the actual UDP dynamic range again. The runtime itself refuses a staged SkipAsSource address, changed port-policy boundaries, unexpected installed bytes, a wrong task identity, unsafe key ACLs, a config not exactly in the reviewed ASCII shape, or already-held ports. Its native argv repeats nonsecret bind/auth/limit restrictions; no key appears in argv. It runs only from the protected config directory with a relative basename. The canonical task-owner launcher confines ownership to that task; `Server-Log.js` keeps its log rolling and aged to 90 days through a fixed no-shell native adapter.

## Native dependency security boundary

The supplier is maintained coturn 4.19.1 at source 222c0eb8288be29630d30b5f81085524a0b6fa28. Its reviewed Windows CI dependency baseline is vcpkg dd3097e305afa53f7b4312371f62058d2e665320. That bundle contains OpenSSL 3.5.1, libevent 2.1.12+20230128, libpq 16.9, mongo-c-driver/libbson 1.30.3, hiredis 1.3.0, libmicrohttpd 1.0.1, pthreads 3.0.0, SQLite 3.50.3, utf8proc 2.10.0 and zlib 1.3.1 plus MSVC runtimes. Exact runtime hashes are the pin, not these display versions.

OpenSSL 3.5.1 is **not patched for later advisories**. The permitted configuration therefore exposes only IPv4 UDP TURN/STUN authentication and opaque relaying, using digest/HMAC operations in `src/client/ns_turn_msg.c` (HMAC around205 and MD5 around400). It may not be reused for TLS/DTLS, HTTP administration, database backends or arbitrary crypto formats. In the immutable supplier source, `mainrelay.c:3598` defaults DTLS off, and `dtls_listener.c:1178`,1181 and1322 gate all UDP DTLS-handshake parsing on that flag. Generated config and argv do not enable it; TCP/TLS are disabled, no DB/HTTP/admin configuration is accepted, and runtime endpoint inspection refuses any TCP listener. Relayed native DTLS/SRTP is opaque peer data, not OpenSSL DTLS termination.

The [official OpenSSL advisory index](https://openssl-library.org/news/vulnerabilities-3.5/) lists later high-severity DTLS, CMS/PKCS7 and PKCS12 issues. The DTLS entry requires the disabled DTLS parser, and the CMS/PKCS APIs have no call sites in this coturn source. This is a reachability restriction, **not a claim that the entire dependency bundle is patched or suitable for other modes**. Enabling another mode requires a patched package and a fresh dependency/security review. The DB/HTTP libraries are linked but receive no untrusted database/HTTP input in this closed configuration. No remote database or admin endpoint is started.
