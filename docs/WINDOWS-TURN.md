# Windows TURN relay

Refs #6561. This is an operator-only UDP relay on the Windows game VPS, separate from game/client payloads. Dev verification precedes Main activation. Source, configuration, protected keys, task identity and actual network endpoints are independently checked; no fallback runtime is started on refusal.

## Build and trust

`records/turn/pion-windows.json` pins the official portable Go toolchain by SHA256 and Pion TURN v5.1.3 by source commit and Go checksum-database hashes. `tools/turn-relay/go.mod` and `go.sum` lock the transitive module graph. `New-PionPackage.ps1 -GoArchive <verified-official-zip> -SourceCommit <reviewed-full-sha> -OutputDirectory <new-directory>` builds the exact archived source, runs its tests, and records executable/dependency hashes. The foreground Windows executable is self-contained: no runtime installation, OpenSSL, database or HTTP admin interface. Retain the reviewed source, official SDK archive and package for reproducible repair/rollback.

Only `-version` or `-config <absolute-path>` is accepted. Configuration is bounded, strict UTF-8 JSON with exactly eight fields; duplicate/case-alias/unknown keys, nonpublic/noncanonical IPv4, relative key paths and altered role boundaries are refused. The key is 64 lowercase ASCII hex characters in a protected file, not hex-decoded and never placed on argv/environment or printed. Authentication preserves the issuer's expiring numeric username plus HMAC-SHA1 password, using TURN's long-term message integrity. Failed/expired/far-future credentials do not allocate.

## Network and resource boundary

Dev uses UDP listener3478, allocation ports42000–42031, realm `turn-dev.thornswood.net`, and task `Thornswood Dev TURN`. Main is separate: listener3479, ports42032–42063, realm `turn-main.thornswood.net`, independent key/task. Both blocks are below the measured Windows IPv4/IPv6 dynamic UDP start49152; the live source and dynamic ranges are rechecked on every startup. No TCP, TLS, DTLS termination, UDP6 or administrative listener is available. Relayed peer DTLS/SRTP is opaque data.

Each role retains32 total allocations,8 per credential bucket,65536 bytes/second per allocation and2097152 bytes/second global, with one second burst capacity. Both media directions share each allocation's byte budget. Numeric-expiry usernames are credential buckets, not unique people/IPs; a native voice client can allocate once per pair. These are initial bounded capacities, not proof of a full game-room workload. Capacity increases require explicit review and measurement.

Unauthenticated admission uses a fixed4096-bucket IP hash,1000 packets/second per bucket and8000 global, with equal one-second bursts. Colliding addresses share the bucket. Listener output is bounded to2097152 bytes/second. Counters are aggregate only; no raw identity/address, secret or audio is logged. Fixed allocation/ingress buffers read full-size UDP datagrams, then discard oversized data before copying to Pion's smaller buffer; packet-size errors cannot accidentally kill an allocation. Drops iterate, never recurse.

Private, link-local, multicast, reserved and IPv6 peers are refused. Permission checks are insufficient for co-location because TURN permissions contain an IP but no destination port. The returned allocation PacketConn therefore guards **actual reads and writes**. Every other local public IPv4 alias is blocked. For this relay's configured public IP, only an active socket owned by the same role is admitted; merely being inside the configured range is insufficient. Windows address notifications register before the immutable startup snapshot. Pending notifications suspend forwarding; unchanged/private-only notifications resume it, while actual public-alias changes or failed enumeration stop the relay with an explicit reason. Operators stop relays before planned host address changes; OS notification delivery is asynchronous. This avoids an expensive enumeration per media packet. Destination lease validation remains locked across the local send, and Close revokes the lease before another local service can inherit that port. Different-role allocations cannot be reached through the same-IP exception. Other public destinations retain ordinary TURN semantics.

Allocation bind/reservation and quota accounting are atomic. Failed binds consume no lease, and idempotent Close releases the port/user count once. Optional Pion EVEN-PORT probes are bounded temporary leases; requested ports are checked before binding, including reservation allocations. Shutdown closes owned allocations and refuses new ones.

## Host sequence and rollback

`Install-PionRelay.ps1 -Step Stage -Role dev -RelayIPv4 <verified-source> -PackageDirectory <reviewed-package> -PackageHash <exe-sha256> -SourceCommit <reviewed-source>` creates a fresh protected root and a **disabled** task. It refuses existing roots/tasks. The task uses canonical restricted LOCAL SERVICE plus its unique task SID and only SeChangeNotifyPrivilege, with no SYSTEM fallback. Code/config/key are read-only to that task; only logs are writable. Its no-shell adapter uses canonical Server-Log rotation/90-day retention. Runtime repeats source, config, secret ACL, package hash and exact identity checks.

`-Step Verify` reads the disabled stage and checks its exact source, package hash and task identity. `-Step Activate` establishes a bounded maintenance hold, adds program-specific UDP ingress through the Group Policy store, and verifies the active rule and listener before recording activation. Failure disables the role's task and removes its rule. `-Step Stop` stops and disables that role and removes its rule. Activate Main after the Dev media test and the protected Main deployment. Pass its full deployed commit as `-ExpectedMainCommit`. The calls verify that commit, the Dev relay's activation receipt and Dev's live issuer endpoint before opening Main UDP.

`Switch-DevTurnRelay.ps1 -Step Inspect -RelayIPv4 <verified-source> -ExpectedDevCommit <actual-current-dev-sha>` is read-only. `-Step Switch` checks zero peers, people and tracked in-world profiles immediately before a coordinated Dev-only restart. It preserves the task-SID owner action, retains protected Oracle key/action rollback, changes only the Dev relay URL and protected key atomically, and verifies the actual served short-lived credential's HMAC. Main preservation compares PID plus actual process StartTime/source/mode, never a derived wall-clock health timestamp. This is a coordinated short restart, not an atomic admission barrier; operators clear their own test sessions first. The explicit `-AllowChatOnlyMaintenance` option permits remaining unplaced signaling sockets only while people and tracked counts remain zero, reporting their count without identity. The default still requires zero sockets. Canonical task validation checks actual SID, unique safe environment bindings, the complete Dev command chain/working directory and source-derived owner executable path/hash plus trusted filesystem owner/write ACL.

A canonical hold covers the issuer transaction. A partially completed stop must be observed as stopped before replacing credentials. Failure restores the protected Oracle key/action; unknown termination leaves the bounded hold and avoids a second issuer. `-Step Rollback -ReceiptDirectory <exact-receipt>` restores the retained Oracle issuer; stop the Windows relay separately **after** that issuer is verified. Never delete old credentials, replay uncertain messages or change Main during Dev maintenance.

`Switch-MainTurnRelay.ps1 -Step Switch -RelayIPv4 <verified-source> -ExpectedMainCommit <deployed-main-sha>` adds the separately verified Main endpoint to the running Main release. It requires an empty Main session list, an active Main relay and an issuer with no prior TURN setting or key. It preserves the restricted task configuration and verifies the ephemeral credential's HMAC from the actual local issuer. `-Step Rollback -ReceiptDirectory <exact-receipt>` restores the former task action and removes the key added by that transaction after checking its hash. Both operations compare the running Dev process identity before and after.

## Acceptance

Automated Go regressions exercise real loopback TURN challenge/message integrity, expiring credentials, authenticated bidirectional data, forbidden same-host marker delivery, closed-port reuse, quota concurrency, transport/range refusal, throttling and oversized packet survival. A private negative control disabling the send guard fails at actual marker delivery. Loopback permits a test-only allocator address; production configuration always requires public IPv4.

Before activation, independently review exact source/dependency scan, build/package hashes and host transaction, then prove the same-host marker negative and allocation-to-allocation positive on the VPS using only owned temporary ports. Parent operations owns public two-network native ICE/DTLS/SRTP/Opus acceptance and explicit Dev issuer switch approval. Synthetic/loopback packets do not prove user microphones or public connectivity. Main receives a separate key/role test and protected-release authorization after Dev verification.
